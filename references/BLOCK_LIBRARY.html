Element types: what connects bodies

A system file wires bodies together with these 11 element types. Each acts along a measure (for example hub + $R_tip * rotor - target) and the compiler applies the equal and opposite force to every body in it. Catalog blocks below supply their numbers (stiffness, yield tables, drag constants) through derived:.

Spring that yields and keeps a permanent set. Tables come from builders such as beam_plastic_spring or plastic_indentation_table. break_at removes it after a set amount (punch-through, tear-off).

type: pin
f = k g + c dg/dt on the gap vector g between two points (2d / 3d)

2D and 3D. Holds a point on one body to a point on another with a stiff spring-damper in every direction, so the bodies turn freely about it: a hinge in 2D, a ball joint in 3D (two pins along a line make a 3D hinge). Use k well above the other stiffnesses; the solver's time step follows it.

fields
k, c
out
force, measure, absorbed_work, dissipated
elements:
  hinge:
    type: pin
    measure: [chassis.root, face.root]
    k: 5e7 N/m
    c: 200 N s/m
type: contact_friction
F = mu |F_n| tanh(v_t / v_eps), along the contact surface (2d / 3d)

2D and 3D. Sliding friction on a contact element: rides on that contact's normal force and acts along its surface, so it stops when the contact separates. Rolling, skidding and scraping come out of it.

fields
contact, mu, v_eps
out
force, measure, absorbed_work, dissipated
elements:

    type: contact_friction
    contact: tyre_on_floor
    mu: 0.8
    v_eps: 1 mm/s

Catalog blocks

Builders run once before the sim (material plus geometry to numbers). Analytic blocks are closed-form answers for sizing and checks. Kernels run every time step; the ones marked with an element type are already driven by the compiler. <name> in a snippet is a value you fill in, with units (10 mm, 12000 rpm).
